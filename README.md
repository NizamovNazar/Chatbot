# OA Smart Assistant

**OA Smart Assistant** — вебзастосунок, який я розробляю в межах магістерської кваліфікаційної роботи «Інтелектуальний чат-бот для сайту університету». Його призначення — допомагати знаходити інформацію про Національний університет «Острозька академія»: вступ, освітні програми, навчання, університетські сервіси та студентське життя.

Чат-бот працює українською та англійською мовами. Для підготовки відповідей він використовує матеріали офіційних сайтів академії та, за потреби, зовнішні мовні моделі. Якщо відповідь ґрунтується на документах, користувач отримує посилання на джерела.

Проєкт містить інтерфейс чат-бота, серверну частину, базу знань, адміністративну панель і засоби аналізу звернень. Демонстраційну версію розгорнуто на Railway.

## Що реалізовано

- **Діалог із чат-ботом:** запитання у вільній формі українською або англійською та продовження розмови з урахуванням її контексту.
- **Пошук у базі знань:** поєднання текстового пошуку, офлайн семантичного індексу та підходу Retrieval-Augmented Generation (RAG).
- **Відповіді з джерелами:** посилання на офіційні сторінки, матеріали яких використано для відповіді.
- **Швидкі запитання та FAQ:** налаштування поширених запитів і перевірених відповідей.
- **Оцінювання відповідей:** позитивні та негативні відгуки користувачів.
- **Адміністративна панель:** перегляд журналу звернень, керування FAQ, аналітика, відгуки та формування звітів.
- **Контроль запитів:** окрема перевірка частини небезпечних або явно сторонніх звернень до пошуку й генерації відповіді.

Розклад у поточній версії використовує демонстраційні дані. Проєкт не є офіційною інформаційною системою університету.

## Принцип роботи

Коли користувач надсилає повідомлення, сервер аналізує його зміст та контекст діалогу. Для запитань за тематикою університету виконується пошук відповідних фрагментів у базі знань, створеній з публічних матеріалів академії.

Знайдені фрагменти використовуються для формування відповіді. За наявності доступного AI-провайдера система може залучити мовну модель; якщо вона недоступна, передбачені локальні механізми пошуку та отримання інформації з документів. Результати звернень і відгуки використовуються для журналу та аналітики адміністративної панелі.

Оскільки база знань має обмежене охоплення, не кожне запитання можна підтвердити доступними джерелами. Бот повинен повідомляти про брак відомостей, а не вигадувати факти.

## Структура проєкту

```text
web/       Клієнтський інтерфейс чат-бота та адміністративна панель
server/    API, обробка звернень, пошук, робота з базою даних
shared/    Спільні визначення для клієнта й сервера
scripts/   Допоміжні сценарії запуску та перевірки
```

## Локальний запуск

Для запуску потрібні **Node.js 24.x** (рекомендовано 24.22.3 або новішу версію цієї гілки) і npm.

**1. Отримання коду та встановлення залежностей**

```powershell
git clone https://github.com/NizamovNazar/Chatbot.git
cd Chatbot
npm ci --prefix server
npm ci --prefix web
```

**2. Налаштування середовища**

Створіть `server/.env` на основі `server/.env.example` та вкажіть власні параметри. Ключі зовнішніх AI-провайдерів потрібні тільки для звернення до відповідних моделей. Паролі й API-ключі не можна зберігати в Git або передавати через змінні `VITE_*`.

Для змістовної роботи чат-бота потрібна підготовлена база знань. Саме встановлення залежностей не завантажує корпус документів.

**3. Запуск сервера**

```powershell
npm run dev --prefix server
```

**4. Запуск інтерфейсу в іншому терміналі**

```powershell
npm run dev --prefix web
```

За типової локальної конфігурації чат доступний за адресою `http://localhost:5173/`, адміністративна панель — `http://localhost:5173/admin.html`, а API працює на порту `5000`.

## База знань

Для збирання та індексації публічних матеріалів офіційних сайтів передбачено команду:

```powershell
cd server
npm run index
```

Команда оновлює корпус документів. Її слід запускати лише в підготовленому середовищі, розуміючи, що дані будуть змінені.

У режимі PostgreSQL стан підключення можна перевірити через:

```powershell
npm run sql:status
```

Початкове наповнення PostgreSQL виконується окремо, тільки для заздалегідь перевіреної порожньої бази. Не запускайте початкове наповнення на базі, яка вже містить робочі дані.

## Адміністративна панель

Адміністративна панель відкривається за шляхом `/admin` або `/admin.html`. Для доступу використовується авторизація з перевіркою пароля. У серверному середовищі можна використовувати scrypt-хеш замість збереження пароля у відкритому вигляді.

Створення хешу:

```powershell
cd server
npm run auth:hash
```

Отримане значення вказують у приватній конфігурації як `ADMIN_PASSWORD_HASH`. Облікові дані та ключі не входять до репозиторію.

## Перевірка роботи

Автоматизовані тести серверної частини:

```powershell
npm test --prefix server
```

Перевірка збірки клієнтської частини:

```powershell
npm run build --prefix web
```

У репозиторії є тести окремих сценаріїв API, маршрутизації запитів, роботи з даними та безпекових перевірок. Автоматичні тести з підставними відповідями мовних моделей не замінюють експериментальної оцінки якості відповідей на реальних запитаннях.

## Призначення проєкту

OA Smart Assistant розроблено як практичну частину магістерської кваліфікаційної роботи. Проєкт демонструє побудову університетського інформаційного помічника з базою знань, генерацією відповідей, посиланнями на джерела та адміністративними інструментами для аналізу звернень.
